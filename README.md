Task Manager API
REST API для управления задачами пользователей. Проект реализован на
FastAPI и использует PostgreSQL для хранения данных. Доступ к
задачам ограничен авторизованным пользователем: каждый пользователь
может работать только со своими задачами.
Возможности
- Регистрация пользователя и аутентификация.
- JWT-аутентификация и обновление токена.
- Создание, просмотр, обновление и удаление задач.
- Получение списка задач с пагинацией через limit и offset.
- Разделение логики на слои: routes, services и repositories.
- Работа с PostgreSQL через SQLAlchemy.
- Управление схемой базы данных с помощью Alembic.
- Автоматизированные тесты с Pytest.
- Запуск приложения и базы данных через Docker Compose.

Архитектура
В проекте используется разделение ответственности между слоями:
- Routes --- HTTP endpoints, получение параметров запроса и
  формирование ответа.
- Services --- бизнес-логика.
- Repositories --- операции чтения и записи данных в базе.
- Models / Schemas --- модели базы данных и схемы валидации
  запросов и ответов.
Такое разделение помогает изолировать бизнес-логику от HTTP-слоя и
работы с базой данных.
Запуск через Docker Compose
Требования
- Docker
- Docker Compose
1. Клонируйте репозиторий
git clone <URL_ВАШЕГО_РЕПОЗИТОРИЯ>
cd <ПАПКА_ПРОЕКТА>
2. Настройте переменные окружения
Проект использует следующие переменные для подключения к PostgreSQL:
DB_HOST=db
DB_NAME=your_database
DB_USER=your_user
DB_PASSWORD=your_password
Укажите значения, соответствующие вашей конфигурации Docker Compose.
Если проект использует файл .env, создайте его в корне проекта.
3. Запустите приложение
docker-compose up --build
В конфигурации Docker Compose запускаются приложение и PostgreSQL; перед
запуском приложения выполняются миграции Alembic, если это настроено в
compose-файле.
После запуска API обычно доступен по адресу:
- API: http://localhost:8000
- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc
Остановить контейнеры:
docker-compose down
Чтобы также удалить данные базы, сохранённые в Docker volume,
используйте docker-compose down -v. Внимание: это удалит данные
базы данных в соответствующем volume.
API
Аутентификация
  Метод    Endpoint            Описание
  POST   /users/register   Регистрация пользователя
  POST   /users/login      Вход и получение токенов
  POST   /users/refresh    Обновление токена
Точный формат тела запроса и ответа определяется Pydantic-схемами
проекта. Для защищённых endpoints передавайте access token в заголовке:
Authorization: Bearer <access_token>
Задачи
  Метод      Endpoint             Описание
  POST     /tasks             Создать задачу
  GET      /tasks             Получить список задач текущего пользователя
  GET      /tasks/{task_id}   Получить задачу по ID
  PUT      /tasks/{task_id}   Обновить задачу
  DELETE   /tasks/{task_id}   Удалить задачу
Список задач поддерживает пагинацию:
GET /tasks?limit=10&offset=0
- limit --- максимальное количество задач в ответе.
- offset --- количество записей, которые нужно пропустить.
Операции с задачами выполняются в контексте текущего авторизованного
пользователя. Пользователь не должен иметь доступ к задачам других
пользователей.
Миграции базы данных
Для управления схемой базы данных используется Alembic. Если в проекте
настроена стандартная конфигурация Alembic, миграции можно применять
командой:
alembic upgrade head
При запуске через Docker Compose миграции могут выполняться отдельным
сервисом или командой запуска контейнера --- ориентируйтесь на
docker-compose.yml.
Тестирование
Тесты проекта написаны с использованием Pytest. Запуск тестов локально:
pytest
Если тестам требуется отдельная база данных или переменные окружения,
настройте их перед запуском. Для изоляции тестов рекомендуется
использовать отдельную тестовую БД.
Пример рабочего сценария
1. Зарегистрировать пользователя через POST /users/register.
2. Выполнить вход через POST /users/login.
3. Передать access token в заголовке
   Authorization: Bearer <access_token>.
4. Создать задачу через POST /tasks.
5. Получить список своих задач через GET /tasks.
6. Обновить задачу через PUT /tasks/{task_id} или удалить через
   DELETE /tasks/{task_id}.
